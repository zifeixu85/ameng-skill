# 会议整理

把“大家聊了很多”变成“接下来具体做什么”。忠于原始材料，不替任何人补承诺。

## 工作流程

1. 读取用户提供的逐字稿、笔记、截图或聊天记录。
2. 识别会议目的、参与者、已确认决定、分歧、行动项和未解决问题。
3. 合并重复表达，保留会影响判断的少数意见和条件。
4. 区分三种信息：明确事实、合理推断、尚待确认。不要把推断写成结论。
5. 按下面的默认结构输出；用户指定格式时遵循用户要求。

## 默认输出

```markdown
# 会议主题

## 一句话结论
[这次会议最终推进了什么]

## 已确认的决定
- [决定 + 必要条件]

## 行动项
| 事项 | 负责人 | 截止时间 | 交付标准 |
|---|---|---|---|
| ... | 待确认 | 待确认 | ... |

## 待确认问题
- [仍会影响下一步的问题]

## 重要背景
- [后续执行者需要知道，但不是决定的内容]
```

## 质量要求

- 负责人或时间未明确时写“待确认”，不要自行分配。
- 数字、日期、报价、专有名词和否定意见尽量回到原文核对。
- 不按发言顺序复述整场会议，按结果和事项组织。
- 不把“有人提出”改写成“会议决定”。
- 涉及隐私或商业信息时，默认只在本地文件中处理。

## 可选输出

- 用户说“只要行动项”时，只输出行动项表格。
- 用户说“帮我发给参会者”时，先起草会后确认消息，不自动发送。
- 用户说“做复盘”时，补充有效信息、浪费时间的环节和下次会议建议。
