# Phase 0 需求澄清 intake — 问题设计

开工前用**一次** `AskUserQuestion` 调用对齐方向。原则：

- **能少问就少问**。用户在触发消息里已经说清的项，直接跳过。
- 一次最多 4 题，互斥单选为主。
- 每题给「推荐项放第一个」，让用户能一键走默认路径。
- 主题/关键词如果用户没给，第一步先口头确认，不必占用一道选择题。

## 推荐的四道题

### Q1 · 产出模式（几乎总要问，最影响报告形态）

> 这次研究你想要什么产出？

| 选项 | 含义 | 报告止于 |
|-----|------|---------|
| 仅研究盘点（推荐起步） | 客观呈现「有哪些、各是什么」，不下判断 | 第 6 节 |
| 研究 + 推荐 | 加上「该装哪些、怎么组合、避开哪些」 | 第 7 节 |
| 研究 + 设计方案 | 再加自建 / 拆分 Skill 的设计草案 | 第 8 节 |

### Q2 · 深度

> 要扫多广？

| 选项 | 含义 |
|-----|------|
| 快扫（推荐） | 每来源取最相关代表，约 Top 10，快出结论 |
| 彻查 | 30+，尽量收全去重，适合要做决策/选型 |

### Q3 · 目标 Agent / 宿主

> 你主要在哪个 Agent 上用这些 Skill？（决定兼容性分析侧重）

| 选项 | 含义 |
|-----|------|
| Claude Code | 侧重 Claude Code 可直接装的；标注 hooks/slash 等专属特性 |
| Codex | 侧重 Codex 可用的 |
| OpenClaw / Hermes | 侧重 Agent 工作区生态 |
| 不限 / 都看 | 全收，兼容性逐个标注 |

### Q4 · 使用场景一句话

> 你最终想拿这些 Skill 干嘛？（一句话，决定报告取舍与推荐口径）

这题适合放进 AskUserQuestion 的自由文本，或直接口头问。
例：「我想给团队搭一套小红书内容生产线」「我在选一个能直接发 X 的方案」。

## 跳过规则示例

- 用户说「帮我研究下做 PPT 的 skill，看看有哪些就行」→ 模式=仅研究、已隐含，只需补 Q2/Q3。
- 用户说「我想选一个能在 Claude Code 里直接用的 SEO skill」→ 模式≈推荐、宿主=Claude Code 已给，只需补 Q2。
- 用户说「彻底调研一遍 X 领域的 skill 并给我自建方案」→ 四项基本都有了，可不问直接开干。

## 记录方式

把最终确认的四项写进报告开头「## 1. 研究设定」：

```markdown
## 1. 研究设定
- 主题 / 关键词：...
- 产出模式：research-only / +推荐 / +设计方案
- 深度：快扫 / 彻查
- 目标 Agent：...
- 使用场景：...
```
